# §4 — Decode primitives (cheat-sheet)

Sibling of `sample_queries/common_query_patterns.md` (the hub). `§N` references point to the hub;
pattern templates (P1–P16) live in `query_patterns.md`.

| Need | Snippet |
|------|---------|
| **Callable functions — the whole decode/convert set, and the one that does NOT exist** | `decode_event`, `decode_function`, `decode_function_safe`, `hex_to_numeric`, `hex_to_bytea` (schema `common`, reachable unqualified or as `common.*`), plus the `common.*` / `<chain>.*` helpers in the rows below. **There is no `keccak`, no `keccak256`, no `digest`** — pgcrypto is not installed (core `md5()`/`sha256()` exist but are not keccak). Every `keccak256(…)` written anywhere in this corpus describes an **off-chain** or **on-chain** derivation; none of them is callable in SQL. A topic0/selector is therefore always a precomputed literal. **Wrong:** `WHERE l.topic0 = keccak('Saved(address,uint192)'::bytea)` → `ERROR: function keccak(bytea) does not exist`. **Right:** `WHERE l.topic0 = '\xf195ce54b48d5147da31c1fc525c8828b8836088b505a329e5de2b35da6731e2'::bytea  -- Saved(address,uint192)`. Get the literal from the protocol ref, from `cast keccak "Saved(address,uint192)"`, or by **lookup** (a table read, not a hash — verified/decompiled events only): `select selector from common.event_selector_signature where signature = 'Saved(address,uint192)'`. Run that lookup as its own scratch query and paste the 64 hex into your monitoring query — **never inline it as a subquery**: it drops the indexed-lead plan, leaves an unannotated literal-free filter, and returns 0 rows silently when the event is not in the table. Best of all, hand the signature to the `logs()` macro (`macros.md`) and let it inline the literal for you. |
| Selector of a call | `common.selector(td.calldata)` |
| **Which param is in a topic vs in `data`** | The event's `indexed` flags decide — **not** position in the signature. Indexed params fill `topic1`, `topic2`, `topic3` **in declaration order** (max 3); non-indexed params are ABI-encoded into `data`, also in declaration order, word 0 first. The two runs are counted **separately** — a param's data-word index counts only the non-indexed params before it. **A bare signature carries no flags at all** (`Saved(address,uint192)` says nothing about which param is a topic), so read them from the protocol ref's `## 1. Topics` table (the Quick-copy block strips them) or from `common.event_selector_signature` (`inputs` jsonb, one `indexed` per param; look up by `signature` or by `selector` = topic0). Never guess — wrong flags read the wrong 32-byte word and still return rows. Worked example at the foot of this file. |
| Indexed address from `topic1`/`topic2` | `substring(log.topic1 FROM 13 FOR 20)::bytea` (right-most 20 of 32 bytes) |
| `uint256` from `log.data` | `common.hex_to_numeric('0x' || encode(log.data, 'hex'))` — **only correct when the non-indexed body is a SINGLE word.** Decoding a multi-word body whole concatenates every word into one several-hundred-digit number (a 5-word Morpho `Liquidate` body is 160 bytes). For a multi-word body take one word (next row). |
| **One 32-byte word out of a multi-word `log.data`** | `common.hex_to_numeric('0x' \|\| encode(substring(l.data FROM 33 FOR 32), 'hex'))` — `substring` is **1-indexed**, so word **N** (0-based) starts at **`32N + 1`**: words at `FROM 1`, `33`, `65`, `97`, `129`, … **Off-by-one straddles two words** (`FROM 32` returns 76 digits of garbage, not an amount). **Prefer the signature-form macro** (`macros.md`), which returns decoded *named* columns and removes the offset arithmetic — hand-decoding is the fallback. Verify the result with the decode gate (`../decode-verification.md`). |
| `uint` packed in an indexed topic (e.g. UniV3 fee in `topic3`) | `get_byte(topic3::bytea, 29)*65536 + get_byte(topic3::bytea, 30)*256 + get_byte(topic3::bytea, 31)` — cast `ethword`→`bytea`; last 3 bytes = `uint24` |
| **Readable address/hash in SELECT** | `concat('0x', encode(col, 'hex'))` (or `'0x' \|\| encode(col, 'hex')`) — bare `encode()` has **no `0x`**; output-only, WHERE literals stay `\x` bytea. |
| **`tx_hash` in the result** | **Prefer the function `<chain>.tx_hash(block_number, tx_index)`** — `concat('0x', encode(<chain>.tx_hash(x.block_number, x.tx_index),'hex'))`. **Verified present on all 8 chains** (ethereum/base/arbitrum/optimism/polygon/binance/avalanche/robinhood), so use it on `logs`/`transaction_detail`/`token_ledger`/`token_transfers` instead of joining `outer_transaction`: one fewer table — and it **keeps the large `outer_transaction` table out of the cold working set** (a real win on multi-chain UNIONs, where the cold set is the usual cause of a first-run timeout). `outer_transaction` still exposes `tx_hash` natively when it's already your driving table. Fallback (only if `validate-query` ever flags a missing `tx_hash()`): **JOIN** `{{outer_transaction(network=…, duration=…)}}` `ot ON ot.block_number = x.block_number AND ot.tx_index = x.tx_index` (1:1, **no fan-out**). |
| Token amount → human units | divide by **`pow(10::numeric, decimals)`** — the **`::numeric` base is load-bearing**: a bare `pow(10, decimals)` resolves to `pow(double precision, double precision)` and returns **`double precision`**, which floats the amount and loses digits past `2^53` (`pg_typeof(pow(10, 6::smallint))` = `double precision`). Ship the raw value as `::text` alongside the scaled one (`../decode-verification.md` Check 6). Source `decimals` from `latest_token_info` (row below); inline a constant only for a single pinned well-known token (USDC=6, WETH=18, WBTC=8, USDT=6). |
| **ERC20 metadata (`symbol`/`name`/`decimals`)** | JOIN `<chain>.latest_token_info lti ON lti.token_address = <token_addr_col>` — `symbol`, `token_name`, `decimals` (smallint), `total_supply`. PK `token_address` → **1:1, no fan-out**. Referenced raw (no macro). |
| **USD value (one-call convenience — silently 0 for unpriced tokens)** | `<chain>.to_usd_value(raw_amount, token_address)` → USD `numeric`, **decimals + price handled internally** (raw `1e18` WETH → market $). One call, no manual `pow(10::numeric,decimals)`/price join. Per-chain function — prefix the chain. Works on any numeric (incl. signed `value_delta`). **For an auditable USD figure prefer the explicit `network_token_info` LEFT JOIN (next row)** — `last_price` is kept up to date there and a missing price surfaces as NULL instead of a silent 0; reserve `to_usd_value` for quick one-offs where every token is known-priced. **⚠ Returns `0` for any token with no `last_price` — notably stablecoins** (USDC/USDT/DAI `last_price` is NULL; they are the USD quote unit): `to_usd_value(1e6, USDC)` → **`0`**, NOT `1.00`. If a value leg can be a stablecoin, price it manually with the pinned-$1 COALESCE (next row), never this. |
| **USD price — the proper, auditable join (+ decimals / symbol / logo)** | JOIN `<chain>.network_token_info nti ON nti.token_address = <token_addr_col>` (PK, 1:1): `last_price` (double, **kept up to date — the canonical price source; join it for prices rather than leaning on `to_usd_value`'s hidden lookup**), `symbol`, `decimals`, `logo_small/medium/large`, `presentation_symbol`. (`latest_token_info` has **no price**.) Manual USD = `raw / pow(10::numeric, nti.decimals) * nti.last_price` (**`10::numeric`, never a bare `10`** — see the human-units row); **cast for `round`:** `round((… * nti.last_price)::numeric, 2)` (`last_price` is double; `round(double,int)` doesn't exist). **LEFT JOIN** so rows survive a missing price. **Stablecoin `last_price` is NULL** (USDC/USDT/DAI = the quote unit) → pin to $1 **by address**: `COALESCE(nti.last_price::numeric, CASE WHEN <token_addr_col> = ANY(ARRAY['\x…usdc…'::bytea,'\x…usdt…'::bytea]) THEN 1.0 END)` — **never** a blanket `COALESCE(…, 1)` (misvalues a genuinely unpriced *volatile* token at $1). Verify per chain which collaterals are NULL before trusting a USD sum. |
| **As-of / historical USD price (value *at the time*, not now)** | `common.historical_token_price` (raw; `common` schema, cross-chain via `chain_id`) holds `price`/`cap`/`total_supply` per `ts` (~30-min cadence, occasional multi-hour gaps). **Point-in-time value** = bridge block→time, take the nearest *prior* sample: `LEFT JOIN LATERAL (SELECT price, ts FROM common.historical_token_price h WHERE h.token_address = <tok> AND h.chain_id = <id> AND h.ts <= <chain>.block_timestamp(<blk>) ORDER BY h.ts DESC LIMIT 1) p ON true` — rides the `(token_address, chain_id, ts DESC)` index, `LIMIT 1` = no fan-out. Add a **max-staleness guard** (`AND h.ts >= <chain>.block_timestamp(<blk>) - interval '2 hours'`) so a stale sample isn't silently applied across a gap. `price`/`cap` are `float8` → cast `::numeric` before `round`; nullable → **LEFT JOIN, surface NULL**. **Stablecoins ARE priced here** (≈1.0), so this — not `to_usd_value`/`network_token_info` — is the source for historical stablecoin USD and **depeg** (`abs(price - 1.0) > threshold`). Rule of thumb: `network_token_info.last_price` = **now**; `common.historical_token_price` = **then / over time**. |
| **Live on-chain view call** | `{{ eth_call("<addr_col>.totalSupply()", outputs="( uint256 output0 )", network='<chain>') }}` reads current contract state at tip (→ `<chain>.eth_call(addr, 'sig(returns)', jsonb_build_array(args))`). With args: `"<addr_col>.balanceOf(address owner)"`. **One RPC per row** — use only on a **small** row set (post-aggregation, a param'd address, a `LIMIT`ed set), never across a big scan. For balances prefer `token_balance`. |
| **Holder balances / top-N / concentration** | `<chain>.token_balance` (raw, no macro), `value` = current raw balance. Holders of a token: `WHERE token_address='\x…' AND value > 0 ORDER BY value DESC LIMIT N` (token_address-leading PK). Balances of an address: `WHERE owner_address='\x…'` (owner index). **Add `value > 0`** for holder counts / concentration / registry-of-holders / supply sums — `token_balance` is a never-pruned snapshot, so fully-exited holders persist as stale `value = 0` rows. Omit it only when a zero balance is the point (ex-holders, or investigating a specific token↔wallet combo that holds nothing). No block-range needed — current-state snapshot. |
| **DEX pool / pair → pool-ID resolution (`dex_pool`)** | `<chain>.dex_pool` (raw, no macro; **BNB = `binance.dex_pool`**) maps **token pair → pool** for **Uniswap V2/V3/V4 families + every fork** — Aerodrome/PancakeSwap/Sushi/… all normalize to `project_name ∈ {'Uniswap V2 Pool','Uniswap V3 Pool','Uniswap V4 Pool'}` (the AMM **standard**, *not* the brand — the specific DEX is `factory_address`). **2-token only; Curve/Balancer/multi-token are NOT indexed.** Cols: `pool_tokens` (`ethaddress[2]`), `pool_address`, `factory_address`, `fee` (V3/V4 hundredths-of-a-bip; `8388608`=`0x800000`=V4 dynamic-fee), `metadata` jsonb (V3/V4 `tick`/`sqrtPrice`; **V4 `id`+`hook`+`tickSpacing`**). **Index-backed ONLY on `pool_tokens[1]`, `pool_tokens[2]`, `pool_address`** — lead with one of these; a `project_name`/`factory`/`fee`-only filter is a multi-M-row **seq scan**. Companion `<chain>.dex_pool_activity (pool_address, last_active_block)` = liveness. **Designed pivot = token(s) → the pool "ID":** • **pair → pools** — test **both orderings** (`pool_tokens` is **NOT reliably sorted**, ~0.35% have token0>token1 → no `least()/greatest()` shortcut): `WHERE (pool_tokens[1]=A AND pool_tokens[2]=B) OR (pool_tokens[1]=B AND pool_tokens[2]=A)`; • **token → all its pools**: `WHERE pool_tokens[1]=X OR pool_tokens[2]=X`; • **reverse pool→pair**: `WHERE pool_address='\x…'` — but **`pool_address` is NOT unique** (fork factories emit creation events with arbitrary/colliding addresses; spurious rows resolve `None` tokens) → disambiguate by `factory_address`. **Uniswap V4 (the headline use):** pools aren't contracts — every V4 pool shares `pool_address` = the **PoolManager singleton**, so reverse-by-address is useless and `dex_pool_activity` is coarse; the real per-pool key is **`metadata->>'id'` = the bytes32 PoolId** (the keccak256 of `PoolKey`, computed on-chain by the PoolManager — not a SQL call; same pair + different hook/fee/tickSpacing ⇒ a *different* PoolId → expect several). Monitor a specific V4 pair's swaps = token-pivot → `decode(metadata->>'id','hex')` set → `WHERE address=<PoolManager> AND topic0=\x40e9cecb9f5f1f1c5b9c97dec2917b7ee92e57ba5563708daca94dd84ad7112f AND topic1 = ANY(<ids>)` (V4 `Swap(PoolId indexed id,…)` → `topic1`=PoolId). **Perf:** a pivot keyed on a **mega-token** (WETH/USDC/USDT) builds a large per-token bitmap → may **cold-timeout** (token-volume-bound, like the high-volume-token caveat); a specific token is instant. |
| **Is an address a contract? / contract creation** | Classify: `JOIN {{contracts(network=…)}} c ON c.address = <addr_col>` (present ⇒ contract). A **contract-creation tx** has empty recipient: `outer_transaction.to_a = '\x'::bytea`. "Contract deployed a new contract" = creation tx whose `from_a` is in `contracts`. (Deployer→deployed enumeration is P11.) |
| **Contract code similarity (suspicious upgrade — how much did the logic change?)** | Canonical = **decompiled-function embeddings**, not raw bytes: per implementation, `{{contracts(network=…)}} c ON c.address = <impl>` → `c.md5_bytecode`, then `(SELECT avg(embedding) FROM common.decompiled_public_function_embeddings WHERE md5_bytecode = c.md5_bytecode)` per side, scored with `common.cosine_distance(old_emb, new_emb)` (≈0 = same logic, larger = rewrite). **NULL discipline:** a fresh implementation may not be decompiled/embedded yet → a NULL embedding means **unknown, not similar** — LEFT JOIN, surface the NULL, never COALESCE it away. Cheap pre-filters only: `c_old.md5_bytecode <> c_new.md5_bytecode` (changed at all); pg_trgm `similarity()` on bytecode hex / `decompiled_code.source_level` is a quick-and-dirty **fallback**, not the house method. Form old→new pairs with P2 on `Upgraded(address indexed implementation)` + `LAG(impl) OVER (PARTITION BY proxy ORDER BY block_number, log_index)`. |
| **chain_id literal — function form** | `<chain>.get_chain_id()` returns the numeric chain id (`ethereum`→1, `base`→8453, …) — cleaner than hardcoding `8453 AS chain_id`. |
| **Mint / burn detection** | Transfers to/from the zero address: in `token_ledger`, `WHERE address = '\x0000000000000000000000000000000000000000'::bytea` → `value_delta > 0` = **mint**, `value_delta < 0` = **burn**. Sum per period for net supply change. |
| **Deviation / drift between two prices (÷0-safe)** | `abs(a - b) / GREATEST(abs(a), abs(b))`; alert when `> threshold` (e.g. `0.01` = 1%). `GREATEST` avoids divide-by-zero and normalizes both directions — for oracle-vs-market or feed-vs-feed drift. |
| **1:1 enrich from a table that may match >1 row** | `LEFT JOIN LATERAL (SELECT col FROM {{token_ledger(...)}} tl WHERE tl.block_number=x.block_number AND tl.tx_index=x.tx_index AND tl.address='\x…' AND tl.value_delta = x.amount LIMIT 1) e ON true` — the `LIMIT 1` inside guarantees **no fan-out** (safer than the match in a plain `JOIN … ON`). |
| **Force a topic0-led scan when a single pinned `address` would otherwise win** (rare event, busy contract, topic0-indexed chain) | A lone `address = '\x…'` (or a 1-element `IN`, which folds to `=`) makes the planner read *all* that contract's logs and over-estimate the row count (→ `latest_token_info` seq-scans). Fence a **topic0-only** scan, filter the address outside: `FROM (SELECT block_number, tx_index, address, topic1, topic2, topic3, data FROM {{logs(network=…, duration=…)}} WHERE topic0 = '\x…' OFFSET 0) l … WHERE l.address = '\x…'`. **`OFFSET 0`** blocks predicate-pushdown/flattening so the inner scan uses the `(topic0,block_number,address)` index; the outer `address` filter still excludes fork emitters that share the topic0 (e.g. Aave-forks emitting Aave's `LiquidationCall`). Lighter than `… AS MATERIALIZED` (no temp write). Only needed for a **single** pinned address — for ≥2, `address = ANY(ARRAY[…])` already keeps topic0 leading. |
| **Token NOT carried in the event (resolve in-tx)** | When an event omits a token you need (e.g. Morpho `Liquidate` carries only market `id`) but the token *moves in the same tx*, read it from `token_ledger`: its row has `value_delta` magnitude = the event's amount. Use the LATERAL recipe above with `tl.address='\x<contract>'` and `tl.value_delta = <amount from event>` → `tl.token_address` is the token (Morpho seized-collateral = `value_delta = +seizedAssets`; repaid loan = the `-repaidAssets` row). Resolves **in-window** — no registry TABLE, no materialization. **Price each amount with ITS OWN token** (collateral vs debt vs Morpho `badDebtAssets`, which is *loan*-denominated). **Only works if the *underlying* moves:** cToken/eVault-share/aToken-share seizes (Compound V2 `seizeTokens`, Euler V2 `yieldBalance`, Aave V4 `liquidatedShares`) move a *wrapper* token that isn't USD-priced — fall back to `eth_call` (`exchangeRateStored`/`convertToAssets`/reserveId→asset) to convert shares→underlying. |
| **`chain_id` in the result** | Project a literal matching the network — `8453` base, `1` ethereum, `42161` arbitrum, `10` optimism, `137` polygon, `56` bnb, `43114` avalanche, `4663` robinhood. In a cross-network `UNION`, each branch carries its own literal. |
| Time-bucket | `date_trunc('hour', <chain>.block_timestamp(block_number))` |

## Worked example — a mixed event, decoded by hand

`Supply(address indexed reserve, address user, address indexed onBehalfOf, uint256 amount, uint16 indexed referralCode)`
(Aave V3 Pool — `references/protocols/aave/v3.md` §1.1). Five params: **3 indexed** fill `topic1..topic3`
in declaration order, **2 non-indexed** are the `data` body, words 0 and 1. Position in the signature is
not the layout — `user` is param #2 but **data word 0**, and `onBehalfOf` is param #3 but **`topic2`**.

| param | # in sig | `indexed` | lives in |
|---|---|---|---|
| `reserve` | 1 | yes | `topic1` |
| `user` | 2 | no | `data` word 0 (`FROM 1 FOR 32`); address = its last 20 bytes → `FROM 13 FOR 20` |
| `onBehalfOf` | 3 | yes | `topic2` |
| `amount` | 4 | no | `data` word 1 → `FROM 33 FOR 32` |
| `referralCode` | 5 | yes | `topic3` |

```sql
SELECT
    concat('0x', encode(substring(l.topic1 FROM 13 FOR 20), 'hex'))                 AS reserve,       -- indexed #1 -> topic1
    concat('0x', encode(substring(l.data   FROM 13 FOR 20), 'hex'))                 AS "user",        -- non-indexed #1 -> data word 0 (address = last 20 of the word)
    concat('0x', encode(substring(l.topic2 FROM 13 FOR 20), 'hex'))                 AS on_behalf_of,  -- indexed #2 -> topic2
    common.hex_to_numeric('0x' || encode(substring(l.data FROM 33 FOR 32), 'hex'))   AS amount         -- non-indexed #2 -> data word 1
FROM {{logs(network='ethereum', duration='24h')}} l
WHERE l.topic0 = '\x2b627736bca15cd5381dcf80b0bf11fd197d01a037c52b927a881a10fb73ba61'::bytea  -- Supply(address,address,address,uint256,uint16)
  AND l.topic1 IS NOT NULL AND l.topic2 IS NOT NULL AND l.topic3 IS NOT NULL                   -- 3 indexed params
```

Note the mandatory topic0 comment is the **flag-stripped** canonical form (`indexed` is dropped before
hashing, so all four spellings of this event share one topic0) — the comment therefore cannot tell you the
layout either. Only the flagged signature can.

**Prefer the macro** — it reads the same flags and returns named columns, no offset arithmetic:
```
{{logs(network='ethereum', duration='24h', inputs='Supply(address indexed reserve, address user, address indexed onBehalfOf, uint256 amount, uint16 indexed referralCode)')}}
```
It expands to a `decode_event('{… "indexed": true/false …}', topic0, topic1, topic2, topic3, data)` join.
`decode_event` splits topics from `data` purely by the ABI's `indexed` flags. On the macro path a wrong
flag changes the folded `topicN is null` / `is not null` guards → **silent 0 rows** (`macros.md`). Calling
`decode_event` directly, a wrong indexed **count** raises a decode error, while flags on the **wrong params**
with the right count mis-assign silently. Confirm the expansion with `preprocess-query` (render must show
the expected `topicN is not null` guards and `"indexed"` values).
