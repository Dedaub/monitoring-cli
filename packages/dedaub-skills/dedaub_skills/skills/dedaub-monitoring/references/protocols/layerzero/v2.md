# LayerZero V2 — Topics, Selectors, Addresses (Ethereum, Base, BNB, Avalanche, Arbitrum, Optimism, Polygon, Robinhood Chain, Arc)

**Status:** verified against live RPC on every listed chain and the canonical `LayerZero-Labs/LayerZero-v2` repo + the official deployments metadata registry on 2026-06-09. Re-checked on 2026-09-29: every EndpointV2 event re-derived from `IMessagingChannel`/`IMessagingComposer`/`IMessageLibManager`/`ILayerZeroEndpointV2` (three rows corrected, §1.1), the OFT standard added (§1.5, §2.4, §4.2), and Robinhood Chain (4663, eid 30416) added (§4.1). Arc (5042, eid 30417) added on 2026-10-05 (§4.1a).
**Scope:** LayerZero V2 generic-messaging stack — `EndpointV2`, the message libraries `SendUln302`/`ReceiveUln302`/`ReadLib1002`, the `Executor` + `LzExecutor`, `DeadDVN`, `BlockedMessageLib` and `EndpointV2View` — on Ethereum (1), Base (8453), BNB Smart Chain (56), Avalanche C-Chain (43114), Arbitrum One (42161), Optimism (10), Polygon PoS (137), Robinhood Chain (4663) and Arc (5042); plus the OFT token standard built on it and the major OFT deployments of those chains. Topics/selectors are chain-agnostic; addresses are network-specific. V1 (Endpoint + UltraLightNodeV2) is documented separately in [v1.md](./v1.md).

LayerZero V2 is a **generic cross-chain messaging protocol**, not a token bridge: it moves arbitrary bytes between chains. Applications (OFTs, OApps) call into `EndpointV2`, which dispatches the outbound message to a configured **send message library** (`SendUln302`) and accepts inbound verification through a **receive message library** (`ReceiveUln302`). Security is modular — each OApp picks a set of **DVNs** (Decentralized Verifier Networks) and an **Executor**; there is no single privileged relayer like V1. The single workhorse event for indexing outbound traffic is **`PacketSent`** emitted by `EndpointV2`; inbound is **`PacketVerified`** then **`PacketDelivered`**.

**`EndpointV2` is deployed at one deterministic address — `0x1a44076050125825900e736c501f859c50fE728c` — on the seven older target chains** (and on most LayerZero V2 EVM chains). **Robinhood Chain and Arc are the exceptions: both use EndpointV2 `0x6F475642a6e85809B1c36Fa62763669b1b48DD5B`** (eid 30416 on Robinhood Chain, eid 30417 on Arc; `0x1a44076050125825900e736c501f859c50fE728c` has no code on either). It is **immutable / non-upgradeable** (EIP-1967 impl slot reads `0x0`), as are the ULN message libraries and `ReadLib1002`. The **`Executor` and `LzExecutor` are the only upgradeable pieces** (EIP-1967 Transparent proxies). Message-library addresses are **per-chain** (different on every network) and are *registered* into the Endpoint, then selected per-OApp; an OApp that has not overridden config uses the Endpoint's default send/receive library for the destination `eid`.

> **`eid` ≠ `chainId`.** LayerZero V2 addresses chains by **Endpoint ID** (`eid`), a protocol-internal identifier with no relation to EVM `chainId`. Mainnet V2 eids are `30000 + n`. The nine targets: Ethereum `30101`, BNB `30102`, Avalanche `30106`, Polygon `30109`, Arbitrum `30110`, Optimism `30111`, Base `30184`, Robinhood Chain `30416` (read live: `EndpointV2.eid()` = `0x76d0`), Arc `30417` (read live: `0x76d1`). Confirmed live: `EndpointV2.eid()` on Ethereum returns `0x7595` = `30101`. Always translate `eid → chainId` from the registry, never assume.

**Flow and value movement.** Source: the user calls `send` on the OFT (or on a router that calls it); in the same transaction an **adapter** pulls the ERC-20 (`Transfer` user → adapter, a lock) or a **native OFT** burns (`Transfer` user → `0x0`); then `OFTSent` and the Endpoint's `PacketSent`. Destination: the Executor calls `EndpointV2.lzReceive` → `PacketDelivered` → the OFT releases (`Transfer` adapter → user) or mints (`Transfer` `0x0` → user) and emits `OFTReceived`. **Link key = `guid`** (indexed topic1 of both events; also inside `PacketSent.encodedPayload`). Amounts are in local decimals after dust removal to `sharedDecimals` (usually 6): `amountSentLD` can exceed `amountReceivedLD`. A failed destination call leaves the packet verified but undelivered (`LzReceiveAlert` on the Endpoint); there is no on-chain refund path — the packet is retried, cleared or nilified on the destination.

## 7. Detection invariants & gotchas

1. **`eid` ≠ `chainId`.** Every V2 event/struct uses `srcEid`/`dstEid` (uint32), not EVM chainId. Mainnet eids are `30000+n` (ETH 30101, BNB 30102, Avax 30106, Polygon 30109, Arbitrum 30110, Optimism 30111, Base 30184, Robinhood Chain 30416, Arc 30417). Translate via the registry; never assume.
2. **`PacketSent` is the outbound workhorse and has NO indexed fields.** Filter by emitter (`EndpointV2` `0x1a44…728c`) + topic0; you cannot pre-filter by destination. The destination/sender/nonce/guid live inside `encodedPayload` — decode the packet header.
3. **`guid` is the cross-chain join key.** Match a source `PacketSent` to a destination `PacketVerified`/`PacketDelivered` by `guid` (bytes32). `(srcEid,sender,nonce)` is the equivalent tuple key carried in the `Origin` struct of inbound events.
4. **EndpointV2 is the same address on the seven older targets** (`0x1a44076050125825900e736c501f859c50fE728c`) **but not on Robinhood Chain or Arc** (both `0x6f475642a6e85809b1c36fa62763669b1b48dd5b`). A filter on the `0x1a44076050125825900e736c501f859c50fE728c` literal alone misses all Robinhood Chain and Arc traffic, and a filter on `0x6f47…dd5b` alone mixes the two. Do NOT use the Endpoint address to distinguish chains — use `chainId` from your RPC and `eid()` from the contract.
5. **Message libraries are per-chain and per-app-selectable.** An OApp can override its send/receive library (`SendLibrarySet`/`ReceiveLibrarySet`). If you only watch the default `SendUln302`, you miss apps on a custom library. To capture *all* outbound traffic, key off `EndpointV2.PacketSent` (every send funnels through the Endpoint regardless of library).
6. **V2 address-role collision:** Optimism `SendUln302` == Polygon `ReceiveUln302` == `0x1322871e4ab09Bc7f5717189434f97bBD9546e95`. Key on `(chainId, address, role)`.
7. **`UlnConfigSet` topic0 is shared between SendUln302 and ReceiveUln302.** Disambiguate by emitting library address (send-side vs receive-side config).
8. **DVN verification is multi-event.** One `PayloadVerified` per DVN on `ReceiveUln302`; the packet is only `PacketVerified` (on the Endpoint) once the app's required-DVN threshold is met. A `PayloadVerified` alone does not mean delivery.
9. **Failed execution emits an alert, not a revert log loss.** `LzReceiveAlert`/`LzComposeAlert` fire when the Executor's `lzReceive`/`lzCompose` reverts — the packet stays verified-but-undelivered and can be retried via `clear`. Monitor alerts as stuck-message signals.
10. **`nilify`/`burn` are message-kill paths.** `PacketNilified`/`PacketBurnt` mean an OApp/owner invalidated a verified payload (security action). Rare but high-signal.
11. **Only the Executors are upgradeable.** Endpoint + ULN libs are immutable; a "protocol upgrade" is a new library registration, surfaced by `LibraryRegistered`/`DefaultSendLibrarySet`/`DefaultReceiveLibrarySet` on the Endpoint — treat those like an `Upgraded` event.
12. **ZRO fee is opt-in.** `EndpointV2.lzToken()` returns `0x0` on Ethereum even though the ZRO token (`0x6985…71cd`) exists; apps must opt into `payInLzToken=true`. Don't assume ZRO is wired as the fee token.
13. **`BlockedMessageLib` (`0x1ccbf0db9c192d969de57e25b3ff09a25bb1d862`, same on the seven older targets; Robinhood Chain and Arc use `0xc1ce56b2099ca68720592583c7984cab4b6d7e7a`) reverts on use** — if an OApp's configured lib resolves to it, that pathway is intentionally disabled.
14. **OFT transfers are keyed by `guid`.** `OFTSent` (source) and `OFTReceived` (destination) carry the same indexed `guid` as the Endpoint's packet. The emitter is the token contract: an adapter (locks the ERC-20; `Transfer` user → adapter) or a native OFT (burns; `Transfer` user → `0x0`). Keying on the topic alone (any emitter) finds every OFT, including unknown ones; key on the address to follow one token (§4.2).
15. **`amountSentLD` ≥ `amountReceivedLD`.** OFTs remove dust below `sharedDecimals` (usually 6) and some charge a fee; the recipient gets `amountReceivedLD`. Use `OFTReceived.amountReceivedLD` for the payout.
16. **`PeerSet` is the OFT kill-switch and the hijack vector.** A new peer on a pathway lets that remote contract mint or release on this chain. Alert on `PeerSet` (`0x238399d427b947898edb290f5ff0f9109849b1c3ba196a42e35f00c50a54b98b`) from every monitored OFT, together with `EnforcedOptionSet`, `MsgInspectorSet` and the Endpoint's `SendLibrarySet`/`ReceiveLibrarySet` for the OFT.
17. **Robinhood Chain and Arc share their own V2 stack literals** (eid 30416, §4.1; eid 30417, §4.1a) and have no ZRO token.
