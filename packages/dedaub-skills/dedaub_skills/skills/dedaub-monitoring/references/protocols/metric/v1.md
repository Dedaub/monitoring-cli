# Metric (metric.xyz) V1 — Topics, Selectors, Addresses (ETH, Base, BNB, Avax, Arb, Polygon, Robinhood)

**Status:** verified on 2026-10-30 against live RPC on Ethereum (1), Base (8453), BNB (56), Avalanche (43114), Arbitrum (42161), Polygon PoS (137) and Robinhood Chain (4663); absence checked on Optimism (10) and Arc (5042). ABIs from the Sourcify full-match source of `MetricOmmPoolFactory`, `MetricOmmPool` and `MetricOmmSimpleRouter`; addresses from the official deployments page.
**Scope:** the Metric V1 oracle-guided AMM ("Active Pools", `MetricOmm*` contracts): factory, pool deployer, pools, periphery, extensions and the oracle / price-provider layer. Topics and selectors are chain-agnostic. Addresses are the same on every listed chain.

> **Not the same protocol as Metric.exchange.** This file covers **Metric (metric.xyz, `github.com/Metricxyz`)**, a 2026 oracle-guided DEX. The METRIC token and the founder fleet in [`core.md`](core.md) and [`founder-fleet.md`](founder-fleet.md) belong to the older, unrelated **Metric.exchange** front-end. No on-chain link between the two was found. Do not mix them in one monitor.

Metric V1 pools do not price on a curve. Each pool reads bid / ask / reference prices from an external **Price Provider** (Chainlink Data Streams, Pyth, a compressed oracle, or a multiplier oracle for tokenized stocks) and holds liquidity in **bins** around that price. A **curator** (pool admin) picks the price provider and the fees; LPs pick bins. All contracts are deployed through CreateX / CREATE2, so each contract has **one address on every chain**. No contract in the set is a proxy (EIP-1967 implementation slot is empty).

Two factory generations exist. The **current** `MetricOmmPoolFactory` `0x2a53…8f32` was deployed in one wave on **2026-09-15** (Ethereum block 25,984,373). The **retired** factory `0x6229…EDe4` stopped on **2026-09-22**; its pools are drained. The official page says "only use the addresses on this page" and lists only the current set.

## 5. Proxies

No proxies. The EIP-1967 implementation slot reads `0x0` on the factory, deployer, router and `PriceProviderFactory`. Pools are plain contracts deployed by `MetricOmmPoolDeployer` (~20 KB each). The upgrade-like levers are admin calls on the factory: `setPoolDeployer` (new pools only), `proposePoolPriceProvider` → `executePoolPriceProviderUpdate` (timelocked price-source swap), and the fee setters.

## 6. Detection invariants & gotchas

1. **Price comes from the provider, not from reserves.** A price-provider swap (`PoolPriceProviderChangeProposed` → `PoolPriceProviderUpdated` on the factory, `PriceProviderUpdated` on the pool) changes every future fill price. Treat it as a high-severity admin event.
2. **Key on the pool and check `isPool`.** Pool events carry no pool address in the topics. Use the log emitter and confirm it with `factory.isPool(emitter)` or the `PoolCreated` set. The retired factory's pools are not `isPool` on the current factory.
3. **`Swap` fields are packed.** `amountDeltas` holds two `int128` values (`high` = token0, `low` = token1; positive = pool received). `platformFees` holds two `uint128` values (`high` = spread fee, `low` = notional fee). Decode before you compare amounts.
4. **`sender` is the router or a bot.** `MetricOmmSimpleRouter` `0x0220…aB7` is a top `sender` on Robinhood. Aggregators and solvers also call pools directly.
5. **Retired-factory pools use an older event ABI.** The current `Swap` topic is absent from the retired pools' bytecode. The retired pools are drained. Do not reuse the §1.1 topics on them.
6. **Not Metric.exchange.** The METRIC token `0xefc1…14ac` is unrelated (see [`core.md`](core.md)).
7. **Same address, different code hash** for the router and the liquidity adder. Do not use a code-hash allowlist across chains for those two.
