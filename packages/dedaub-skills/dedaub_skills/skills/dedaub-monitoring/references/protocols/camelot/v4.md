# Camelot AMM v4 (Algebra Integral) — Topics, Selectors, Addresses (Arbitrum)

**Status:** verified 2026-10-30 against live RPC on Arbitrum One (`arbitrum-one-rpc.publicnode.com` for state, `arbitrum.gateway.tenderly.co` for full-history `eth_getLogs`), the official address page [docs.camelot.exchange/contracts/arbitrum/one-mainnet](https://docs.camelot.exchange/contracts/arbitrum/one-mainnet), and the canonical [`cryptoalgebra/Algebra`](https://github.com/cryptoalgebra/Algebra) Integral source (tag `v1.2.1-integral`).
**Scope:** Camelot "AMMv4": a concentrated-liquidity AMM on the **Algebra Integral** engine (core v1.2.x, plugin architecture). It is deployed on **Arbitrum One (42161) only**. `eth_getCode` returns `0x` for every v4 address on Ethereum (1), Base (8453), BNB (56), Avalanche (43114), Optimism (10), Polygon (137), Robinhood Chain (4663) and Arc (5042). Topics and selectors are chain-agnostic. Addresses are network-specific. Other Camelot versions: [v2.md](v2.md) (classic AMM), [v3.md](v3.md) (Algebra V1.9 fork).

v4 is **not** an upgrade of v3. It is a separate factory, pool deployer, NFPM and router. Pools are CREATE2 clones deployed by the AlgebraPoolDeployer. Each pool has one **plugin** contract (dynamic fee, sliding fee, volatility oracle, security registry). The plugin is set by the default PluginFactory at pool creation. Nothing is an EIP-1967 proxy.

**Two v4 factories exist.** The docs list AlgebraFactory `0xBefC4b40…` (live since 2025-10-21). The docs also list a "PluginFactory" `0x222F135D…` and a "CodePairHash" `0xb3fc09be…`. These two values belong to an **earlier** v4 factory `0x6b692b58…` (2024-11-20 to 2025-10-25, 50 pools), not to `0xBefC4b40…`. The live factory uses PluginFactory `0x47408d2a…` and init code hash `0xa18736c3…` (both read live). Monitor both factories. Their pools emit the same topics.

## 6. Detection invariants & gotchas

1. **`Swap` and `Burn` topics differ from v3.** v4 `Swap` = `0x121cb44e…` (9 fields: adds `overrideFee`, `pluginFee`). v4 `Burn` = `0x932214d4…` (adds `pluginFee`). A v3 query on `0xc42079f9…` / `0x0c396cd9…` misses every v4 swap and burn.
2. **`Mint`, `Collect`, `Initialize`, `Flash`, `Fee` and the factory `Pool` topics are the same in v3 and v4.** Disambiguate by the factory that emitted `Pool`. Keep a pool set per factory (v3 `0x1a3c9B1d…`, v4 `0xBefC4b40…` and `0x6b692b58…`).
3. **Two v4 factories.** The docs' "PluginFactory" and "CodePairHash" belong to the earlier factory `0x6b692b58…`, not to the listed AlgebraFactory. Address derivation with `0xb3fc09be…` gives the wrong pool for `0xBefC4b40…` (use `0xa18736c3…` and deployer `0x799d2b52…`).
4. **The effective fee is in the `Swap` data.** `overrideFee` and `pluginFee` come from the plugin per swap. `Fee(uint16)` does not fire on every swap. `lastFee` in `globalState()` is the last stored fee and can be stale under a dynamic-fee plugin.
5. **The plugin is a privileged hook.** `Plugin(address)` and `PluginConfig(uint8)` change which hooks run and can redirect plugin fees. Alert on both. `pluginConfig` = 215 on WETH/USDC (2026-10-30).
6. **`ExcessTokens(uint256,uint256)` fires often** (about 1 in 10 swaps on WETH/USDC). It reports pool balance above reserves. It is not an exploit signal by itself.
7. **Custom pools.** `createCustomPool` (role `CUSTOM_POOL_DEPLOYER`) emits `CustomPool` `0x8a5f030f…`, not `Pool`. A monitor keyed only on `Pool` misses custom pools.
8. **Router params changed.** v4 `exactInputSingle` has a `deployer` field (`0x1679c792…`). v3 selector `0xbc651188` does not match.
9. **`globalState()` has 6 fields in v4** and 8 in the Camelot v3 fork. Decode by version.
10. **Arbitrum only.** No v4 code on the other eight chains.
