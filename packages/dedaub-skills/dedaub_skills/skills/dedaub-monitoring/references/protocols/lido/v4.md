# Lido V4 (protocol v4.1.0) — Topics, Selectors, Addresses (Ethereum mainnet)

**Status:** verified 2026-10-30 against Ethereum mainnet (`eth_getCode`, EIP-1967 slot reads, `eth_getLogs` over blocks 25,546,351–26,306,351), the verified ABIs of every listed implementation, `docs.lido.fi/deployed-contracts` (lists protocol **v4.1.0**), and the `lidofinance/core` `v4.1.0` and `lidofinance/community-staking-module` sources.
**Scope:** the contracts and ABI changes that **Lido v4** (Staking Router v3, LIP-35) and **v4.1.0** (Execution Delegation Framework, LIP-37) add. This file covers CuratedModule v2 (module ID 4), Community Staking Module 0x02 (module ID 5), the consolidation stack, the Top Up Gateway, the CircuitBreaker, the DelegationFactory, and the changed core ABIs (stETH, StakingRouter, AccountingOracle, VEBO, WithdrawalVault). **Lido v4 is on Ethereum mainnet (chain ID 1) only.** Topics and selectors are chain-agnostic. Addresses are Ethereum-specific.

**What v4 changes.** Lido v4 adds **0x02 (compounding, EIP-7251) withdrawal credentials** to the core. A module now holds validators with a balance above 32 ETH. The StakingRouter tracks a **validator balance per module**, not only a validator count. Deposits are split into an **initial deposit** (DSM → `StakingRouter.deposit`) and **top-ups** (TopUpGateway → `StakingRouter.topUp`). Two new 0x02 modules plug into the router: **CuratedModule v2** (permissioned operators, entry by Merkle gates) and **CSM 0x02** (permissionless). The **ConsolidationMigrator → ConsolidationBus → ConsolidationGateway → WithdrawalVault** path moves curated v1 (NodeOperatorsRegistry, module 1) validators into CuratedModule v2 by EIP-7251 consolidation requests. The oracle `ReportData` struct changed again (new `submitReportData` selector `0x11a78d23`).

**Upgrade timeline (on-chain).** The v4 core upgrade executed at block **25,603,297** (2026-07-24 14:47 UTC, tx `0x297042b4…14aa`). That transaction emitted `Upgraded` on AccountingOracle, StakingRouter, VEBO, WithdrawalVault, Accounting, LidoLocator and the seven original-CSM proxies, and `StakingModuleAdded(id 4, CuratedModule v2)`. A second vote at block 26,054,464 (2026-09-25) upgraded LidoLocator again and replaced the DepositSecurityModule. The consolidation path went live on 2026-09-11 (first `ConsolidationPairAllowed`, block 25,953,069). The first top-up ran on 2026-09-22 (block 26,033,084). The CSM 0x02 proxies were upgraded at block 26,103,487 (2026-10-02). The router added CSM 0x02 as module 5 at block 26,255,782 (2026-10-23). The DelegationFactory (v4.1.0) deployed its first instance at block 25,875,175.

> **Read with the older files.** The base stETH, withdrawal, and oracle ABIs are in [v2.md](v2.md). The stVaults additions are in [v3.md](v3.md). This file lists only what v4 adds, removes, or changes.

## 6. Detection invariants & gotchas

1. **Oracle reports and top-ups arrive through DelegationContracts.** On 2026-10-30 the AccountingOracle report tx (`0x12ef0aa5…a512`) goes to `0xc7442d4d…1749`, and the top-up tx (`0x5ad03c0f…ca8c`) goes to `0x6aa249ba…f4c5`. Both are EDF instances that call `execute(address,bytes)` `0x1cff79cd`. `tx.to` is not the AccountingOracle or TopUpGateway. Key on the emitted logs or on internal calls, not on the top-level selector.
2. **New `submitReportData` selector.** v4 uses `0x11a78d23`. A decoder that expects `0x1001587f` (V3) or `0xfc7377cd` (V2) silently misses every report after block 25,603,297.
3. **Balance, not count.** `CLValidatorsUpdated` is gone. Use `CLBalancesUpdated(reportTimestamp, clValidatorsBalance, clPendingBalance)`. Validators on 0x02 credentials hold up to 2048 ETH. A validator count no longer gives the stake.
4. **Two deposit events per module.** `StakingRouterETHDeposited` is the initial deposit (`INITIAL_DEPOSIT_SIZE()` = 32 ETH, via DSM `depositBufferedEther` `0x69c88a26`). `StakingRouterETHTopUp` is the later top-up (via TopUpGateway). Add both to get the ETH that a module received.
5. **Module IDs.** 1 = NodeOperatorsRegistry (curated v1), 2 = SimpleDVT, 3 = CSM, 4 = CuratedModule v2, 5 = CSM 0x02 (read live from `getStakingModuleIds()` / `getStakingModule(uint256)`). Modules 4 and 5 use withdrawal-credentials type 2. Modules 1–3 use type 1.
6. **Topic0 collisions across modules.** CuratedModule v2, CSM 0x02, the original CSM (module 3) and NodeOperatorsRegistry share `SigningKeyAdded`, `DepositedSigningKeysCountChanged`, `NodeOperatorAdded`, and others. The five module Accountings and FeeDistributors also share topic0s. Always filter by the emitter address.
7. **Consolidation is a three-hop flow.** Migrator `submitConsolidationBatch` → `ConsolidationSubmitted` + Bus `RequestsAdded` (same tx). After the 86,400 s delay a bot calls Bus `executeConsolidation` (payable, EIP-7251 fee) → `RequestsExecuted(batchHash, feePaid)`, and the WithdrawalVault emits one `ConsolidationRequestAdded` per pair. The `request` bytes hold the source and target pubkeys.
8. **Migration direction is fixed.** The Migrator only moves module 1 operators into module 4. `ConsolidationPairAllowed` names the operator pair. The submitter must be the allowed address.
9. **DSM and ORSC are new addresses.** The DSM changed twice (block 25,603,297 and block 26,054,464). The ORSC changed once (block 25,603,297). Old filters on `0xfFA9…72fD`, `0xf573…e9be` or `0xf164…3129` see no new events. Resolve both from LidoLocator.
10. **CircuitBreaker replaces GateSeal.** A pause on any listed pausable emits `PauseTriggered(pausable, pauser, duration)` on the CircuitBreaker and `Paused(uint256)` on the target. Each pauser has a heartbeat expiry. `heartbeat()` renews it and emits `HeartbeatUpdated`.
11. **CSM 0x02 is new and small.** On 2026-10-30 module 5 has a 1 bp stake share limit and zero validator balance. Expect low volume.

## 8. Verification & sources

How the constants in this file were verified (2026-10-30):
- **Topic0 / selectors:** recomputed locally as `keccak256(canonical signature)` from the verified ABI of each deployed implementation (Sourcify for most; Blockscout for AccountingOracle, VEBO, MetaRegistry, the CSM 0x02 ParametersRegistry/ValidatorStrikes/Verifier/HashConsensus, DelegationFactory, and the DelegationContract). Every selector in §2 is present as `PUSH4` in the deployed runtime bytecode. The `✓` counts come from `eth_getLogs` over blocks 25,546,351–26,306,351 (all v4 addresses except stETH and WithdrawalVault). stETH and WithdrawalVault counts come from a topic-filtered scan of the last 150,000 blocks.
- **v4 changes:** the "new" and "removed" items come from an ABI diff between the pre-v4 implementations (EIP-1967 slot / Aragon `implementation()` read at block 25,603,296) and the live v4 implementations.
- **Addresses:** from `docs.lido.fi/deployed-contracts` (v4.1.0). Each address was existence-checked with `eth_getCode`. Each proxy impl and admin was read from the EIP-1967 slots. The LidoLocator getters confirm the DSM, ORSC, ConsolidationGateway and TopUpGateway. Module IDs, names, types, and withdrawal-credentials types come from `StakingRouter.getStakingModule(uint256)` and `getType()`.
- **Sibling identity:** the CuratedModule v2 and CSM 0x02 support contracts have identical ABIs (ABI diff). Their bytecode differs only in immutables.
- **Chain coverage:** `eth_getCode` on Base, BNB, Avalanche, Arbitrum, Optimism, Polygon PoS, Robinhood Chain and Arc returned `0x` for all 11 key v4 addresses.
