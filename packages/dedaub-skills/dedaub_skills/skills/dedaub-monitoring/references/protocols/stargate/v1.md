# Stargate v1 — Topics, Selectors, Addresses (Ethereum + Base + Arbitrum + Optimism + Polygon + BNB + Avalanche; NOT Robinhood Chain)

**Status:** verified on 2026-10-01 against live RPC on all eight target chains, the Stargate v1 "Contract Addresses / Mainnet", "Chain IDs" and "Pool IDs" pages, and the `stargate-protocol/stargate` repository. Topics and selectors recomputed as `keccak256(signature)`; addresses existence-checked with `eth_getCode`; proxy slots read live.
**Scope:** Stargate v1 (2022) on LayerZero V1: `Router`, `RouterETH`, `Bridge`, `Factory`, the `Pool` contracts (one per asset and chain), the STG token, the fee library, `StargateComposer`, `WidgetSwap` and LP staking. Deployed on seven target chains: Ethereum (1), Base (8453), Arbitrum One (42161), Optimism (10), Polygon PoS (137), BNB Smart Chain (56) and Avalanche C-Chain (43114). **Not on Robinhood Chain (4663).** Stargate v2 is in [v2.md](v2.md); the LayerZero V1 endpoint and libraries are in [../layerzero/v1.md](../layerzero/v1.md). Topics and selectors are chain-agnostic; addresses are per chain.

A v1 transfer is a pool-to-pool swap. The user calls `Router.swap` (or `RouterETH.swapETH` for native ETH) on the source chain. The Router moves the tokens from the user into the source `Pool` (`Swap` event), the Pool computes the fees and credits, and `Bridge` sends a LayerZero V1 message (`SendMsg`). On the destination chain, the LayerZero V1 endpoint calls `Bridge.lzReceive`, `Bridge` calls `Router.swapRemote`, and the destination `Pool` pays the receiver from its liquidity (`SwapRemote`). Amounts in pool events are in shared decimals (`amountSD`); multiply by the pool's `convertRate()` for the token's own decimals.

v1 is winding down: in the pinned window the v1 pools emitted only LP exits (`InstantRedeemLocal`, `Burn`) and no `Swap` or `SwapRemote` on any chain. In Ethereum blocks 25,880,000–25,929,999 (early September 2026) the Ethereum pools still emitted 8 `SwapRemote` (inbound payouts) and 0 `Swap`. The statement that the v1 pools stop working after 2026-12-15 (when LayerZero stops its V1 relayer) is **unverified** here: it was not found on the official pages that were read.

## 0. Contract families

| Contract | Role | Proxy |
|----------|------|-------|
| **Router** | Entry point: `swap`, `addLiquidity`, `redeemRemote`, `redeemLocal`, `instantRedeemLocal`, `sendCredits`; receives `swapRemote` from Bridge. | not a proxy |
| **RouterETH** | Wraps native ETH into the SGETH pool token and calls Router. A second RouterETH supports `swapETHAndCall`. | not a proxy |
| **Bridge** | The LayerZero V1 application: `SendMsg` on send, `lzReceive` on delivery. | not a proxy |
| **Factory** | Pool registry: `getPool(poolId)`. | not a proxy |
| **Pool** | One per asset and chain; holds the liquidity; emits `Swap` (source leg) and `SwapRemote` (destination leg). | not a proxy |
| StargateToken (STG) | OFT v1 token with its own `SendToChain` / `ReceiveFromChain`. | not a proxy |
| StargateComposer, WidgetSwap | Wrappers with one literal on all seven chains. | not a proxy |

## 6. Detection invariants & gotchas

1. **Source and destination legs.** Source: `Swap` at the source Pool (`chainId` = destination v1 id, `dstPoolId`, `amountSD`), with the ERC-20 `Transfer` user (or Router caller) → Pool in the same transaction, and `SendMsg` at Bridge. Destination: `SwapRemote(to, amountSD, protocolFee, dstFee)` at the destination Pool, with a `Transfer` Pool → `to`.
2. **Link key = the LayerZero V1 nonce.** `SendMsg.nonce` on the source is the outbound nonce of the path (source chain, Bridge) → (destination chain, Bridge). On the destination, the LayerZero V1 delivery log in the same transaction as `SwapRemote` carries the source chain id and the same nonce (sample: Ethereum `0xcf74ae803af7b0d8182f333fd0a86604fd2221ec90bd7048cd345934c5554484`, delivery from v1 chain 110 with nonce 229,617, then `SwapRemote` at the ETH pool). The pool events themselves carry no id. Decode the LayerZero V1 logs as described in [../layerzero/v1.md](../layerzero/v1.md).
3. **`CreditChainPath` is not the payout.** It fires on every delivered message, also for credit-only messages. Key payouts on `SwapRemote`.
4. **Amounts are in shared decimals.** `amountSD × convertRate()` = token units. The pools of 18-decimal tokens have a convert rate above 1.
5. **Native ETH goes through SGETH.** The ETH pools hold SGETH (Ethereum `0x72e2f4830b9e45d52f80ac08cb2bec0fef72ed9c`); RouterETH wraps on the source, and the destination pool unwraps and sends native ETH to `to` (no `Transfer` to the user).
6. **Failed payouts are stored, not refunded.** `Revert` (payout reverted, `retryRevert` later) and `CachedSwapSaved` (tokens paid, `sgReceive` failed) are status events; the matching `SwapRemote` arrives on the retry.
7. **`from` in `Swap` is the Router caller**, often an aggregator or RouterETH, not the end user.
8. **Two id maps and a third for v2.** v1 events carry v1 ids (101 to 184), old history carries the original ids (1, 2, 6, 9, 10, 11), and Stargate v2 carries eids (30101 and up). See §0.
9. **Activity is low.** In the pinned window no v1 pool emitted `Swap` or `SwapRemote` on any of the seven chains; only LP exits (`InstantRedeemLocal`) appeared on Base, Arbitrum, Optimism and Polygon. Do not read a missing v1 event as a missing transfer: users moved to v2 ([v2.md](v2.md)).
10. **Monitor triggers.** Large transfers: `Swap.amountSD` and `SwapRemote.amountSD` per pool. Drains: `SwapRemote` without a matching source `Swap`, `InstantRedeemLocal` spikes. Admin: `OwnershipTransferred`, `StopSwapUpdated`, `FeeLibraryUpdated`, `setBridge` and `forceResumeReceive` calls.
