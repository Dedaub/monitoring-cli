# Ramses V3 (2026 redeploy: CL + DLMM + legacy) — Topics, Selectors, Addresses (Arbitrum, Polygon PoS, Robinhood Chain)

**Status:** verified on 2026-10-30 against live RPC on Arbitrum One (42161), Polygon PoS (137) and Robinhood Chain (4663); absence checked on Ethereum, Base, BNB, Avalanche, Optimism and Arc. ABIs from Sourcify full-match sources; wiring read live from `AccessHub`, `Voter`, NFPM and router views.
**Scope:** the second Ramses concentrated-liquidity generation (`RamsesV3Factory`, tickSpacing-keyed; DefiLlama lists it as "ramses-cl-v2"), its periphery, the new legacy `PairFactory`, and — on Robinhood Chain only — the DLMM (Liquidity Book) engine and the ve(3,3) Voter stack. Topics and selectors are chain-agnostic; addresses are network-specific.

This generation is **not** the fee-keyed CL in [`cl.md`](cl.md) (`RamsesV2Factory` `0xAA2cd7…`, still live on Arbitrum). It is the same engine as Pharaoh CL: `getPool(tokenA, tokenB, int24 tickSpacing)`, and the pool `Mint` carries an extra `uint256 index` (`0xd78218c0…`). One deployer EOA `0xAAA5D87392652647225B96563e469768f000b9De` created every contract with plain `CREATE`, so **the same address holds a different contract on each chain** (for example `0x2bef…2380` is the CL factory on Polygon, the FeeCollector on Robinhood, and a message sender on Arbitrum). Always pair an address with its chain.

## 8. Detection invariants & gotchas

1. **CREATE address reuse across chains.** One deployer, one nonce sequence per chain. `0xd001…d28b` is the CL factory on Arbitrum but the DLMMRouter on Robinhood; `0x2bef…2380` is the CL factory on Polygon but the FeeCollector on Robinhood. Never key on address alone.
2. **Two CL generations on Arbitrum.** The old fee-keyed factory `0xAA2cd7…` ([`cl.md`](cl.md)) and this tickSpacing-keyed factory both emit `PoolCreated` `0x783cca1c…` and pool `Swap` `0xc42079f9…`. Their `Mint` topics differ (`0x7a53080b…` old vs `0xd78218c0…` new).
3. **Uniswap V3 collisions.** `Swap`, `PoolCreated`, `Burn`, `Collect`, `Flash` share topics with Uniswap V3. Confirm the emitter with `factory.isPairV3(pool)`.
4. **Legacy `PairCreated` changed shape.** The new PairFactory emits the 4-arg `0x0d3648bd…` (no `bool stable`). The old Arbitrum factory emits the 5-arg `0xc4805696…`.
5. **`FeeAdjustment` exists twice.** Pool-level `FeeAdjustment(uint24,uint24)` `0x0cba8718…` (≈118 per 29,000 Robinhood blocks) and factory-level `FeeAdjustment(address,uint24)` `0xe4accbae…`.
6. **Governance only on Robinhood.** Arbitrum and Polygon hubs return `0x0` for `voter()`, `minter()` and `xRam()`; those chains run CL and legacy pools without gauges.
