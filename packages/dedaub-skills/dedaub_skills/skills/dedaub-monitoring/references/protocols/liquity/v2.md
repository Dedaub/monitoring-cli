# Liquity V2 (BOLD) — Topics, Selectors, Addresses (Ethereum)

**Status:** verified against live Ethereum RPC and the canonical `liquity/bold` and `liquity/V2-gov` repos on 2026-10-30.
**Scope:** Liquity V2, the BOLD stablecoin system (the May 2025 relaunch), with its three collateral branches (WETH, wstETH, rETH) and the LQTY-staking governance.
Ethereum (chain 1) only. Topics and selectors are chain-agnostic. Addresses are for Ethereum. The other eight target chains have no deployment (§5).

Liquity V2 is a multi-collateral CDP system with user-set interest rates.
One **CollateralRegistry** and one **BoldToken** serve all branches. Each branch has its own TroveManager, BorrowerOperations, StabilityPool, ActivePool, DefaultPool, CollSurplusPool, SortedTroves, TroveNFT and PriceFeed.
All contracts are plain, non-proxy deployments with no owner. Branch parameters (MCR, CCR, SCR) are immutable.

The non-obvious facts for an indexer:
- A Trove is an **ERC-721 token** (TroveNFT). `troveId = uint256(keccak256(abi.encode(msg.sender, _owner, _ownerIndex)))`. The NFT owner is the Trove owner, and the owner can change by NFT transfer.
- All branches emit the **same topic0 values**. The emitter address identifies the collateral.
- Redemptions start at **CollateralRegistry** and cut across all branches in one transaction.
- **Relaunch:** the first V2 deployment (January 2025) was made legacy after a Stability Pool issue. The protocol was redeployed and went live again on 2025-05-19. Legacy BOLD is `0xb01dd87B29d187F3E3a4Bf6cdAebfb97f3d9aB98` (code present). This file documents the relaunch addresses only.

## 0. Contract families

| Contract | Scope | Role |
|----------|-------|------|
| **CollateralRegistry** | global | Redemption entry point; redemption base rate; branch list |
| **BoldToken** | global | BOLD ERC-20 (EIP-2612). Minted by BorrowerOperations / ActivePool, burned in repay and redemption |
| **Governance** | global | LQTY staking, initiative voting; also each branch's `interestRouter` (receives 25 % of interest) |
| **HintHelpers / MultiTroveGetter / DebtInFrontHelper / RedemptionHelper / ExchangeHelpers(V2)** | global | View and helper contracts |
| **TroveManager** | per branch | Trove and batch state, liquidations, redemptions, urgent redemption after shutdown |
| **BorrowerOperations** | per branch | User entry point: open/adjust/close Troves, interest-rate delegates, batch managers, shutdown trigger |
| **StabilityPool** | per branch | BOLD deposits; absorbs liquidations; earns 75 % of interest (`SP_YIELD_SPLIT`) |
| **ActivePool / DefaultPool / CollSurplusPool** | per branch | Collateral and debt accounting |
| **SortedTroves** | per branch | Troves sorted by annual interest rate (redemption order) |
| **TroveNFT** (+ MetadataNFT) | per branch | ERC-721 for each Trove |
| **PriceFeed** | per branch | Chainlink-based price with branch shutdown on oracle failure |
| **AddressesRegistry** | per branch | Wiring and constants (`CCR()`, `MCR()`, `SCR()`) |
| **GasPool** | per branch | Holds the WETH gas compensation (0.0375 WETH per Trove) |
| **Zappers** | per branch | WETH / gas-comp / leverage helpers. They call BorrowerOperations for the user |

Branch parameters read live from AddressesRegistry: WETH CCR 150 %, MCR 110 %, SCR 110 %. wstETH and rETH CCR 160 %, MCR 120 %, SCR 120 %.
Global constants from the deployment manifest: MIN_DEBT 2,000 BOLD; interest rate 0.5 %–250 %; interest-rate adjust cooldown 7 days; upfront fee period 7 days.

## 6. Proxies

No Liquity V2 contract is a proxy. The EIP-1967 implementation slot is zero on CollateralRegistry, BoldToken, the WETH TroveManager and Governance.
`owner()` on BoldToken and Governance returns `0x0`. TroveManager and CollateralRegistry have no `owner()`.
There is no upgrade path and no `Upgraded` event to watch. A fix needs a full redeployment (as happened in May 2025).

## 7. Detection invariants & gotchas

1. **Branch from emitter.** Every branch emits identical topic0 values. Map the emitter to the branch with §4.
2. **Trove key is `troveId` (uint256), not an address.** The current owner is `TroveNFT.ownerOf(troveId)`. A zapper can be `msg.sender` in the id preimage, so you cannot derive the owner from the id.
3. **Liquidations:** `batchLiquidateTroves` emits one `Liquidation` per call (totals and `_price`) plus one `TroveOperation` (`_operation`=5) and `TroveUpdated` per Trove. Large `_debtRedistributed` means the Stability Pool was too small.
4. **Redemptions** go through `CollateralRegistry.redeemCollateral`. Each touched branch emits `Redemption` and one `TroveOperation` (`_operation`=6) per Trove. CollateralRegistry emits `BaseRateUpdated`. A redemption is the main peg-defence signal. Troves below MIN_DEBT after redemption become **zombie** (status 4).
5. **Shutdown:** `BorrowerOperations.ShutDown(tcr)` (TCR < SCR) or `PriceFeed.ShutDownFromOracleFailure(oracle)`. After shutdown, `urgentRedemption` is the only exit. Watch both topics on every branch. `TroveManager.shutdownTime()` is 0 on all three branches on 2026-10-30.
6. **Batch managers** move the rate of many Troves at once. `BatchUpdated` (indexed manager) is the batch event. Troves in a batch emit `BatchedTroveUpdated` instead of `TroveUpdated`.
7. **Signed fields:** `TroveOperation._debtChangeFromOperation`, `_collChangeFromOperation` and `DepositOperation._topUpOrWithdrawal` are `int256`. A negative value is a decrease.
8. **Topic0 shared with V1:** `P_Updated`, `CollBalanceUpdated`, `BaseRateUpdated`, `LastFeeOpTimeUpdated`, and `S_Updated(uint256,uint256)` / `ScaleUpdated(uint256)` (V1 source form, which the V1 deployment does not emit). Filter by emitter.
9. **Interest** accrues without per-Trove events. ActivePool mints BOLD interest to the StabilityPool and the Governance contract when any branch operation runs.
10. **Legacy V2:** the January 2025 deployment still has code (legacy BOLD `0xb01d…aB98`). Do not mix its logs with the relaunch.
11. **Forks** share all topic0 values. Always filter by emitter address.
