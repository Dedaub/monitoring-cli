# Liquity V1 (LUSD) — Topics, Selectors, Addresses (Ethereum)

**Status:** verified against live Ethereum RPC and the canonical `liquity/dev` repo on 2026-10-30.
**Scope:** Liquity V1, the LUSD stablecoin system and the LQTY staking token. Ethereum (chain 1) only.
Topics and selectors are chain-agnostic. Addresses are for Ethereum. The other eight target chains have no deployment (§4).

Liquity V1 is a single-collateral CDP system. Users lock ETH in a "Trove" and borrow LUSD.
The system launched on 2021-04-05 (start block 12178551).
All contracts are plain, non-proxy deployments. The deployer called `setAddresses` one time and then renounced ownership.
The system is immutable: no admin, no upgrade, no parameter change.

The non-obvious facts for an indexer:
- The borrower address is the Trove key. One address has at most one Trove.
- `TroveUpdated` has the same topic0 on **TroveManager** and **BorrowerOperations**. Only the `operation` enum differs.
- The deployed StabilityPool emits `S_Updated`, `G_Updated`, `ScaleUpdated` and `EpochUpdated` with `uint128` epoch/scale fields.
  The `main` branch source shows `uint256` versions. The deployed topic0 values are the ones in §1.3.

## 0. Contract families

| Contract | Role |
|----------|------|
| **BorrowerOperations** | User entry point: open, adjust, close a Trove. Mints and burns LUSD. |
| **TroveManager** | Liquidations, redemptions, Trove state, base rate. |
| **StabilityPool** | LUSD deposits that absorb liquidated debt. Pays ETH gains and LQTY. |
| **ActivePool** | Holds the ETH collateral and the debt total of active Troves. |
| **DefaultPool** | Holds redistributed ETH and debt that are not yet applied to Troves. |
| **CollSurplusPool** | Holds surplus ETH for owners of liquidated or redeemed Troves (claim with `claimCollateral`). |
| **SortedTroves** | Doubly linked list of Troves, sorted by nominal ICR. |
| **PriceFeed** | Chainlink ETH/USD primary, Tellor fallback. |
| **GasPool** | Holds the 200 LUSD gas compensation for each Trove. |
| **LUSDToken** / **LQTYToken** | Stablecoin and protocol token (ERC-20 with EIP-2612). |
| **LQTYStaking** | Stake LQTY to earn ETH redemption fees and LUSD borrowing fees. |
| **CommunityIssuance** | Pays LQTY to Stability Pool depositors. |
| **LockupContractFactory** | Deploys LQTY team and investor lockup contracts. |
| **HintHelpers** / **MultiTroveGetter** | View helpers. |
| **Unipool** | LUSD/ETH Uniswap V2 LP staking for LQTY. The program has ended. |

## 5. Proxies

No Liquity V1 contract is a proxy. The EIP-1967 implementation slot is zero on TroveManager, BorrowerOperations, StabilityPool and LUSDToken.
`owner()` returns `0x0` on TroveManager, BorrowerOperations and StabilityPool (ownership renounced after `setAddresses`).
There is no `Upgraded` event to watch. The code cannot change.

## 6. Detection invariants & gotchas

1. **`TroveUpdated` has two emitters.** BorrowerOperations emits it for user actions (`operation` 0–2). TroveManager emits it for redemptions and pending-reward application (`operation` 0 or 3). Filter by emitter and decode the enum against the matching table in §1.1 or §1.2.
2. **Liquidations:** one `Liquidation` per transaction (batch totals) plus one `TroveLiquidated` per Trove. A liquidation transaction also emits `StabilityPool.P_Updated`/`S_Updated`, and DefaultPool events when debt is redistributed.
3. **Redemptions:** one `Redemption` per transaction plus one `TroveUpdated` (TroveManager, `operation`=3) per redeemed Trove. A Trove fully redeemed is closed. Its surplus ETH goes to CollSurplusPool (`CollBalanceUpdated`).
4. **StabilityPool scale/epoch events** use `uint128` fields in the deployed bytecode. A topic0 computed from the `main` branch (`S_Updated(uint256,uint256)` = `0x79499a…`) never matches V1 logs. That topic belongs to V2 instead.
5. **Recovery Mode** has no event. Compute it: `checkRecoveryMode(price)` or TCR < 150 %. Watch `PriceFeedStatusChanged` for oracle failover (Chainlink to Tellor).
6. **ETH moves as native ETH.** ActivePool, StabilityPool and CollSurplusPool emit `EtherSent`. There is no WETH `Transfer`.
7. **LUSD supply:** mint and burn show as `Transfer` from or to `0x0` on LUSDToken. Only BorrowerOperations, TroveManager and StabilityPool can mint or burn.
8. **Immutable.** Any `OwnershipTransferred` from a core address after 2021-04 is impossible. A change of behaviour cannot come from an upgrade.
9. **Forks** (same topic0 values, other addresses) exist on many chains. Always filter by emitter address.

## 8. Verification & sources

How constants in this doc were verified (2026-10-30):
- **Topic0 / selectors:** recomputed locally as `keccak256(signature)` from `liquity/dev` source.
  Most §1 topic0 values were seen in live `eth_getLogs` on the listed emitters (blocks 26.20M–26.30M).
  `FrontEndRegistered`, `PriceFeedStatusChanged`, `ScaleUpdated`, `EpochUpdated` and `LockupContractDeployedThroughFactory` did not occur in that window. Their topic0 values were confirmed as constants in the deployed bytecode.
  Examples: `Liquidation` and `TroveLiquidated` in tx `0xfac5a6a9d784cfcba149b4573c71398c98a7c4c6d81fc1d33dc8c3ed83dc5ad4`; `Redemption` in tx `0x250a190a0004cba24048b0943c6b2c2aaf8422e8000e763c05bfa00d65223e65`.
  The four `uint128` StabilityPool topics were found as PUSH32 constants in the deployed StabilityPool bytecode. `S_Updated` and `G_Updated` (`uint128` form) also occur in live logs.
  The BorrowerOperations, TroveManager and StabilityPool selectors in §2 were found in the deployed bytecode.
- **Addresses:** parsed from `packages/lib-ethers/deployments/default/mainnet.json` in `liquity/dev`, then existence-checked via `eth_getCode`.
- **Proxies:** EIP-1967 implementation slot read live (zero). `owner()` read live (zero).
- **Chain coverage:** all 18 addresses checked with `eth_getCode` on Base, BNB, Avalanche, Arbitrum, Optimism and Polygon (all `0x`). Key addresses checked on Robinhood Chain and Arc (all `0x`). Bridged LUSD tokens confirmed with `l1Token()` / `l1Address()`.
